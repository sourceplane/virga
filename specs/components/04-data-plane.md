# 04 — data plane

Status: Implemented (VG0 seam, VG1 schema + repositories) · Owner: `packages/db`, `infra/*`

## Seam

`@site/db/d1`: `createSqlExecutor(binding)` translates `$n` placeholders to
D1's positional `?`, normalizes bind values (Date → ISO, boolean → 0/1,
object → JSON), returns `{ rows, rowCount }`. `transaction()` runs statements
in order with no rollback — every call site is a review point.

`@site/db/json`: `parseJsonColumn`, `parseNullableJsonColumn`,
`parseBooleanColumn`.

## Migrations

`packages/db/src/migrations/<NNN_name>/up.sql`, idempotent (`IF NOT EXISTS`
throughout), listed in `manifest.ts` with SHA-256 checksums generated by
`tooling/migrations/rechecksum.mjs`. The runner (`db-migrate` bin) plans on
PRs and applies on merge over D1's REST API, recording into
`_migrations_applied`.

## Repositories

One per context under `src/<context>/`: `types.ts` (stored shapes, inputs,
result union), `repository.ts` (SQL), `index.ts` (exports). Results are
`{ ok: true, value } | { ok: false, error: { kind } }`; unique violations map
to `conflict`.

## Infrastructure

`cloudflare-d1` (one database per environment, adoption at plan time),
`cloudflare-kv` (the rate-limiter namespace, same adoption),
`cloudflare-domain` (parked until the zone exists; a clean v4 root, so a v5
bump is a deliberate two-phase migration), `db-migrate`. Outputs travel as lease-published `WIRING_*`
secrets and are rendered into Worker configs at deploy time.
